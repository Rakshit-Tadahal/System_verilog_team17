01 · Abstract

Project Overview

The Advanced Peripheral Bus (APB) is a low-power bus protocol developed by ARM as part of the AMBA architecture, widely used for communication with peripheral devices in System-on-Chip (SoC) designs. This project presents the complete design and verification of an APB-compliant Register Block implemented in SystemVerilog.

The design implements four memory-mapped registers — Control, Status, Data, and Interrupt — that support standard APB read and write transactions with correct address decoding, read-only status protection, and invalid address handling. A self-checking verification environment was built using Bus Functional Model tasks, SystemVerilog Assertions for protocol compliance, and covergroups for functional coverage. All nine test scenarios execute with zero failures, and all eight protocol assertions pass throughout simulation.
01B · Why APB?

The Role of APB in SoC Design

APB sits at the slowest tier of the AMBA hierarchy, making it the right bus for any peripheral that doesn't need pipelining or burst capability — which describes most control registers.

⚡

Low Power

No pipelining or burst support keeps logic minimal and idle current near zero — critical for always-on peripheral domains.

🔧

Simple Interface

Only ten signals. No handshake complexity — a two-phase (Setup → Access) protocol that any RTL designer can implement in hours.

🧩

Reusable Slave IP

A verified APB slave with a clean register map is a drop-in building block for UART controllers, GPIOs, timers, and watchdog subsystems.

✅

Easy Verification

The deterministic protocol makes assertions straightforward to write and coverage easy to close — ideal for a self-contained verification exercise.

02 · APB Protocol

Signals & Transaction Phases

The APB interface is fully defined by ten signals. Every transaction follows a strict two-phase sequence: Setup Phase followed by Access Phase.

SignalDirectionWidthDescription
PCLKIN1-bitSystem clock — all transfers are synchronous to the rising edge
PRESETnIN1-bitActive-low reset; clears all writable registers to 0
PSELIN1-bitSlave select — asserted in Setup Phase, held through Access Phase
PENABLEIN1-bitEnable strobe — asserted exactly one cycle after PSEL in Access Phase
PWRITEIN1-bitDirection: 1 = write, 0 = read; must remain stable throughout a transfer
PADDRIN4-bitAddress bus — selects target register; must be stable throughout transfer
PWDATAIN32-bitWrite data bus — driven by master during write transactions
PRDATAOUT32-bitRead data bus — driven by slave; valid when PSEL=1 and PWRITE=0
PREADYOUT1-bitTransfer completion — hardwired HIGH (no wait states in this design)
PSLVERROUT1-bitSlave error — hardwired LOW (invalid addresses return 0xDEADBEEF)
Phase 1

Setup Phase

  • PSEL is asserted high
  • PADDR is set to target register address
  • PWRITE signals read (0) or write (1) direction
  • PWDATA is placed on bus for write operations
  • PENABLE remains low throughout this phase
Phase 2

Access Phase

  • PENABLE is asserted on the cycle following Setup
  • All address and control signals must remain stable
  • Write: slave latches PWDATA into target register
  • Read: slave places register value onto PRDATA
  • Transfer completes when PREADY is asserted

03 · Register Architecture

Memory-Mapped Register Block

Four 32-bit registers accessible via APB. The address decoder selects the target register from PADDR. Invalid addresses return the sentinel value 0xDEADBEEF.

CTRL_REG
Control register — stores hardware configuration and control bits. Clears to 0x00000000 on reset. Available on ctrl_out hardware port.

03B · RTL Design Components

Implementation Structure

🔒

Register Storage

Three 32-bit flip-flop arrays for CTRL, DATA, IRQ. STATUS is combinational pass-through from status_in.

🔀

Address Decoder

case(PADDR) statement routes PWDATA to the correct register storage and selects the correct PRDATA source.

📥

Write Path (FF)

always_ff block: clocked by PCLK, triggered when PSEL=1, PENABLE=1, PWRITE=1. Uses non-blocking assignments.

📤

Read Path (Comb)

always_comb block: drives PRDATA immediately when PSEL=1, PWRITE=0. Uses blocking assignments.

🔄

Reset Logic

Active-low asynchronous reset (PRESETn). Clears CTRL, DATA, IRQ to 0 on the negedge. STATUS is not cleared (hardware-driven).

📡

Hardware Ports

Continuous assign connections: ctrl_out, data_out, irq_out, status_in for hardware integration.

04 · Verification Methodology

Self-Checking, Assertions & Coverage

A three-layer verification environment: a Bus Functional Model that generates APB transactions, SystemVerilog Assertions that monitor protocol compliance in real time, and covergroups that track which scenarios were exercised.

04A · SystemVerilog Assertions — 8 Protocol Rules
A1
a_penable_after_psel
PENABLE must be asserted exactly one clock cycle after PSEL is driven high — enforces the single-cycle Setup Phase duration.
operator: |=> (non-overlapping implication, +1 cycle)
A2
a_psel_during_penable
PSEL must remain asserted for the entire duration of the Access Phase. PENABLE high while PSEL low is a protocol violation.
operator: |-> (overlapping implication, same cycle)
A3
a_paddr_stable
PADDR must not change value between the Setup and Access phases. Uses $past() to compare current value against the previous-cycle value during PENABLE.
operator: $past(PADDR) == PADDR during PSEL && PENABLE
A4
a_pwrite_stable
The transfer direction (PWRITE) must remain stable throughout the transaction — no mid-transfer direction flip is permitted.
operator: $past(PWRITE) == PWRITE during active transfer
A5
a_pwdata_stable
Write data on PWDATA must hold stable during the Access Phase of a write transaction to guarantee reliable register captures.
operator: $past(PWDATA) == PWDATA during write Access Phase
A6
a_pready_always_high
PREADY is hardwired to 1 in this design (no wait states). Any clock cycle where it deasserts indicates a synthesis or connection error.
operator: PREADY == 1'b1 at every posedge PCLK
A7
a_no_slverr
PSLVERR must remain low — slave error is handled by the data convention (0xDEADBEEF), not by asserting the error signal.
operator: PSLVERR == 1'b0 at every posedge PCLK
A8
a_penable_deassert
PENABLE must deassert on the cycle following a completed transfer (PENABLE && PREADY). Ensures the bus returns cleanly to idle or setup.
operator: |=> !PENABLE (after PENABLE && PREADY)
04B · Bus Functional Model Tasks
APB_WRITE TASK
1. Wait for posedge PCLK
2. Assert PSEL=1, set PADDR, PWDATA
3. Wait one clock cycle (Setup Phase)
4. Assert PENABLE=1 (Access Phase)
5. Wait one clock cycle
6. Deassert PSEL, PENABLE (Bus Idle)
APB_READ TASK
1. Wait for posedge PCLK
2. Assert PSEL=1, PWRITE=0, set PADDR
3. Wait one clock cycle (Setup Phase)
4. Assert PENABLE=1 (Access Phase)
5. Sample PRDATA output
6. Deassert PSEL, PENABLE (Bus Idle)

06 · Conclusion & Future Scope

What's Next

The verified APB Register Block provides a clean, reusable IP template. Several natural extensions would build on this foundation.

01

APB4 Protocol with PSTRB

Extend the interface to support the PSTRB byte-lane select signal, enabling sub-32-bit (byte and halfword) write granularity per the APB4 specification.

02

Wait-State Insertion via PREADY

Implement a configurable PREADY de-assertion mechanism to model slow peripheral devices and verify master behavior during extended transfer latency.

03

PSLVERR Error Response

Replace the 0xDEADBEEF data convention with a proper PSLVERR assertion on invalid addresses, fully complying with ARM's error-response protocol.

04

UVM-Based Verification Environment

Migrate the testbench to a UVM architecture with a proper agent (sequencer, driver, monitor), scoreboard, and RAL-based register abstraction layer.

05

Formal Verification with SVA Bind

Run formal property checking tools (Cadence JasperGold or Synopsys VC Formal) on the SVA assertions to prove exhaustive correctness beyond simulation.

06

SoC Peripheral Integration

Integrate the Register Block with an APB GPIO or UART peripheral to validate end-to-end SoC subsystem operation with a real software driver stack.
